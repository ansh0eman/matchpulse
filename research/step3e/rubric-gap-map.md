## The required five-stage pipeline

[Official rules §4.1](https://github.com/microsoft/insidethegamehackathon/blob/main/OFFICIAL%20RULES.md#41-hackathon-challenge) describe these stages; they do not make a cached replay equivalent to fresh live inference.

| Stage | Actual path and observable result | Boundary |
|---|---|---|
| Ingest | `poc/src/simulation.ts:runMatch` exports canonical synthetic observations; `agents.cli.load_source` uses `load_match` / `load_frames`. | Catalogued files are loaded locally. No licensed Premier League feed or deployed live-input listener. |
| Interpret | `stories.replay.replay` builds claims; `ClaimRegistry.register` requires verification; scheduler and positional gate decide what is eligible. | Frozen detector findings remain unchanged. A sampled position does not establish coach intent. |
| Explain | `Studio` / `framework.run_graph` select a bounded plan; `compile_narration` derives factual output from approved source. | The saved goal run is genuine Foundry; current viewer browsing is deterministic or source-revalidated recorded presentation. |
| Render | `viewer.service.view` slices events/frames at the clock; `BroadcastTheatre` / `Pitch` render source-derived score, positions and approved moments. | No future score, merged fixture or invented event-only tracking; original and presentation clocks remain distinct. |
| Personalize | `preferences`, eligibility policy and narrative compiler adapt audience/favorite team; `test_personalization_preserves_measurements_and_exposes_detail` checks factual consistency. | Fan/Analyst and favorite team are implemented; languages/player focus are not implied. |

## Release gates outrank further polish

The baseline report records 181 backend tests and 13 browser tests on both native/AMD64 candidates; those counts belong to [Step 3D](../step3d/acceptance.md), not an automatic pass for new changes. Current acceptance must cover score boundaries, backward seeking, cross-match isolation, corrupt/unavailable source, receipt contents, responsiveness and honest provenance. The updated user authorization permits release only after security/licensing/provenance audits and verified no-out-of-pocket hosting. Keep code private until those gates pass; do not claim a live demo, video publication or confirmed entry before observing each result. See [release readiness](release-readiness.md) and [zero-cost decision](zero-cost-hosting-decision.md).
