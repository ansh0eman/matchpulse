## Public viewer boundary

The Docker context is an allowlist. It admits the web source/assets, backend source/lock, eight-file fixture bundle, selected detector configuration and specifically named recorded provenance artifacts. It excludes developer environments, account caches, `.env` files, tests, ignored raw agent outputs and dependency directories. `COPY backend/src` includes provider implementation source, but the public process is the viewer API and carries no developer CLI identity or model secret.

The API accepts closed scenarios, bounded clocks, audience/team values, source-scoped claims and restricted question types. It recomputes approved evidence and enforces prefix/match boundaries; a model or caller supplies no authoritative measurements. Static mounting points at the built web directory, not the repository root. Source errors are bounded; production responses have same-origin CSP and security headers; public hostnames must be allowlisted. No public model/MCP endpoint, arbitrary file upload, prompt, shell or retrieval route exists in the reviewed viewer.

The fully enriched Foundry artifact must continue to pass current source publication verification for its exact preferences. Preserve deterministic/foundry/fallback labels and the unknown historical HTTP request total. Viewer interactions incur no new inference.
