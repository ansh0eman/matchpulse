# Implementation and editorial decisions

Canonical ingestion -> MatchStoryState.update -> typed candidate -> make_claim -> EvidenceIndex.verify -> ClaimRegistry.register -> MatchInsight -> StoryScheduler -> deterministic export.

State retains previous observation, score, one outstanding shot, one latest high regain and a480s shot deque reset on observed period change. Export/index/registry retention is O(total observations/claims); this offline CLI is not a constant-memory service. Verification counts scan source prefixes for independent recomputation; ordinary state updates do not replay the full match. No database, broker, cloud client or model dependency added.

Supported: goal score context (including narrowly worded penalty snapshots), shot attempts, linked saves/misses/blocks in registry, high observed gains, same-possession gain-to-shot, >=3 shots in trailing480s, explicit red cards, observed match boundaries, approved positional claims. Additional useful category is match boundaries/final observable score context, not fabricated novel metrics. Late-goal adjective, assists, possession percentages, pass endpoints, xG, back-four labels and coach intent are withheld.

Rules are editorial definitions, chosen before reviewing outputs; not learned or optimized on holdout accuracy. Attacking activity is >=3 observed attempts (transparent count). Compare with final-third counter: upstream recordPassAttempt can advance target zones before successful reception, so refrain from describing verified ball entries based on those counters. High regain x>=70 uses pitch thirds. Link20s and prior support15s are conservative prototype limits, not football calibration. Same-possession requirement is stricter than time-only linking. Future evaluation should compare human relevance on fresh matches.

Scheduler priority: goal100, dismissal95, boundaries90, sequence80, line70, outcome60, activity50, gain40, shot30. Within the same source event, richer sequence is offered first. One shot incident is narrated once; later shot outcomes remain verified registry updates but are suppressed as incident_already_narrated. High gains and activity have per-team/type120s editorial cooldown. Other routine items occupy4s display slots, max15s delay; goals/boundaries/dismissals bypass routine slots. Equal-time major stories are ordered by priority then ID, without deleting previously accepted prefix items. Delayed facts retain their original source clock; they are never relabeled live measurements. This is a causal policy, not globally optimal future-aware scheduling.

Tracking stays independent: frozen detect/make_pack -> review_episode -> verified line -> same registry/scheduler. No supplied broadcast JSON is trusted unchecked. Events at equal time precede tracking availability at that time. Later frames/events do not affect earlier values. Incomplete/no tracking is safe; score inconsistencies fail the CLI before exports. Output directories should be new per run; existing directories are not an atomic publication endpoint.

Evidence verifier separately reconstructs score transitions, counts, team/player attribution, source times/windows/units, direct possession and shooter relationships. It never calls candidate state or make_claim. It shares canonical contracts, claim identity and semantic definitions. Positional verification intentionally reuses the pre-existing independent geometry/event gate; its own research tests include separate coordinate arithmetic. This is strong finite recomputation evidence, not an independent provider or universal formal proof.
