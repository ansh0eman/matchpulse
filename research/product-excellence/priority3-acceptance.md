In browser traces the successful positional view responses took approximately **1613/1635ms**, and proof responses **38/41ms** (desktop/mobile); no console errors were recorded. ## Remaining defects, ranked by impact

1. **High — prior incident proof flashes during A→B.** Current `inspect()` retains the prior receipt while opening a different claim; the loading state is set later by an effect. The current probe sampled the old positional title for one animation frame on each viewport before the shot summary. Clear or guard proof by the requested claim before rendering the drawer. This is a transient same-fixture incident mismatch; the final receipt is correct. [Captured transient](../../output/playwright/p33/desktop-B-open-transient.png), [frame observations](../../output/playwright/p33/review-evidence.json).
2. **High — withheld headline shares an unrelated event's proof action and timestamps.** Keep the withholding explanation separate from the last recorded shot, or label that shot action explicitly. The API's refusal to publish a positional claim is correct; the failure is what the card invites the fan to inspect.
3. **Medium — keyboard focus is lost on close.** Capture the invoker before drawer autofocus, then restore it after close. Current `useDialog` captures focus after modal autofocus; the saved element is removed with the drawer. Tab trapping itself passed.
4. **Low — comprehension friction.** Shot proof should name the observed action/team; clarify specialist terms with short plain-language text, keep the synthetic-source label visible on mobile, and make the updated explanation easier to find after a mobile timeline selection. These call for small scoped changes, not a redesign.

These defects were documented, not repaired: P3.3 authorized application changes only when narrowly justified by the existing timeout issue. Automated suites passing does not close these observed acceptance gaps.
