# Step3B architecture and official API research

Audit starting state: clean main1483e89, Step3A merged;104 Python tests previously recorded. stories/ schemas/state/claims/evidence/registry/scheduler/replay/export remain the authority; approved tracking.presentation claims are the only positional input. Step3A's conditional verdict and consumed experiment results remain unchanged.

Selected C: conditional typed stages. A sequential analyst/narrator is the comparison baseline; it has less routing/recovery overhead but lacks separate evidence challenge and visual branch. Autonomous group chat is rejected: unbounded turns and shared conversation history add latency, cost and match/time leakage risk. The new workflow selects specialists, selectively challenges, and runs narration/visual planning concurrently; deterministic code publishes facts. There is no database, vector search, broker or agent service per role.

Official sources checked2026-10-23:
- [Framework overview](https://learn.microsoft.com/en-us/agent-framework/overview/) and [workflow concepts](https://learn.microsoft.com/en-us/agent-framework/concepts/workflows/): typed graph and functional APIs; choose graph adapter, with native Python concurrency inside stages.
- [Foundry provider](https://learn.microsoft.com/en-us/agent-framework/integrations/by-component/model-providers/microsoft-foundry): Python Agent + FoundryChatClient uses project Responses inference; separate per-run agents avoid session sharing.
- [Structured output](https://learn.microsoft.com/en-us/agent-framework/agents/structured-outputs): Agent.run options.response_format accepts Pydantic types and returns response.value. This establishes an API design reference, not successful compatibility here.
- [Executors](https://learn.microsoft.com/en-us/agent-framework/concepts/workflows/executors) and [builder](https://learn.microsoft.com/en-us/agent-framework/concepts/workflows/builder-and-execution): typed @handler, WorkflowContext, WorkflowBuilder, terminal outputs. framework.py implements those Python surfaces; no .NET API is copied into Python.
- [Local MCP](https://learn.microsoft.com/en-us/agent-framework/agents/tools/local-mcp-tools): supported stdio tool attachment. Main provider uses direct scoped function tools; optional private stdio server has no HTTP listener.
- [Foundry evaluation](https://learn.microsoft.com/en-us/azure/foundry/concepts/evaluation-overview): service/model evaluators can complement source recomputation, not replace it.
