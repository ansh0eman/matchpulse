# Read-only capabilities

EvidenceTools binds an authoritative replay result, match UUID and maximum clock. Each request validates a closed schema, exact match, finite nonnegative clock<=cap, result count and byte budget. resolve_claim re-runs EvidenceIndex.verify; resolve_evidence resolves only event/tracking ID dictionaries and rejects future observations. get_match_context returns at most8 reverified claims of requested controlled types at/before clock. No file path, URL, SQL, label, external search or write operation exists.

Results are versioned ToolResult objects; data_json preserves source values/units/references. Payload maximum32768bytes. Per-incident model tool budget8; optional private MCP process uses64 across that process lifetime. Calls are redacted to tool name, active scope, clock and outcome; no authentication/prompt content is logged. Direct compiler source resolution is deterministic authority work, not charged against model tool calls.

Provider exposes these as native function tools only to analysts/Challenger. Narrator/Director/Producer have none. Fake-provider tests demonstrate actual local resolver calls, not an LLM deciding to call them. Genuine Foundry model-requested resolve_claim and resolve_evidence now pass the complete live goal-workflow test. Private MCP in-memory is separately verified; do not claim those live calls used MCP transport—the provider uses native scoped functions.

Optional mcp_server.py uses official MCP2 MCPServer and stdio only. Administrator supplies source paths and clock at process startup; tool callers cannot choose sources or widen scope. No public listener or unauthenticated HTTP API is introduced. The private MCP in-memory Client/server test now passes with installed MCP2.3.0. This does not prove stdio subprocess transport or attachment to a live model; those remain unobserved. Official [MCP running-server docs](https://github.com/modelcontextprotocol/python-sdk/blob/main/docs/run/index.md) and [Microsoft MCP tool guide](https://learn.microsoft.com/en-us/agent-framework/agents/tools/local-mcp-tools) informed this boundary. Native function tools remain the supported first provider integration; stdio server is not secretly attached to a live model.
